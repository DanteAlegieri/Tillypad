# Гастродом №3 — Tillypad Dashboard

Первая рабочая версия локального сайта для просмотра данных Tillypad.

## Что уже есть

- проверка подключения к API;
- загрузка подразделений;
- безопасная диагностика любых GET Target;
- загрузка гостевых счетов с JSON-фильтром;
- импорт готового JSON;
- локальная база SQLite;
- показатели:
  - сумма заказов;
  - сумма оплат;
  - количество счетов;
  - средний чек;
  - открытые и закрытые счета;
- журнал синхронизации;
- адаптивный интерфейс.

## Важное ограничение API

В предоставленной документации нет отдельного Target для кассового отчёта,
строк заказа, фискальных чеков и детальных способов оплаты.

Target `Guests` содержит суммы заказа и оплаты, но запрос всех счетов без
фильтра на вашей базе уже завершался timeout. Поэтому проект пока поддерживает:

1. загрузку Guests по узкому JSON-фильтру;
2. импорт полученного JSON;
3. диагностику дополнительных Target.

## Установка

### 1. Распакуйте архив

Например:

```text
C:\TillypadDashboard
```

### 2. Создайте `.env`

Скопируйте `.env.example` и переименуйте копию в `.env`.

Вставьте токен:

```env
TILLYPAD_TOKEN=ваш_токен
```

### 3. Установите библиотеки

Запустите:

```text
install.bat
```

### 4. Запустите сайт

Запустите:

```text
run.bat
```

Откроется:

```text
http://127.0.0.1:8000
```

## Первый запуск

1. Нажмите «Проверить подключение».
2. Нажмите «Загрузить подразделения».
3. Перейдите в «Диагностика API».
4. Проверьте Target `SegmentInfo`.
5. Для `Guests` используйте узкий фильтр, например:

```json
[{"gest_ID":"GUID"}]
```

или номер клиента согласно документации:

```json
[{"gest_clntPhone":"9043028181"}]
```

## Безопасность

- токен хранится только в `.env`;
- браузеру токен не передаётся;
- диагностический интерфейс выполняет только GET-запросы;
- `.env` не нужно никому отправлять.
